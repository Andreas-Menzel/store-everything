| Q58 | **The interim `104` on uploads.** `draft-ietf-httpbis-resumable-upload-12` says a server SHOULD announce the upload resource in a `104 (Upload Resumption Supported)` interim response, *"unless the server is not capable of sending interim responses"* — and ours is not: ASGI defines `http.response.start` and `http.response.body`, and uvicorn sends `100 Continue` and nothing else. What is genuinely unknown is **Apple's background uploader**, whose documentation calls the 104 authoritative ([ADR-0017](decisions/ADR-0017-resumable-upload-protocol.md)); if it refuses to proceed without one, the options are a vendored uvicorn protocol subclass (h11 exposes `InformationalResponse`; the httptools implementation writes bytes directly) or an ASGI server that supports interim responses. Deciding needs a real device pointed at a real instance, which is [F-021](features/F-021-mobile-auto-upload.md)'s phase — not a guess now. | 🔴 |

| Q60 | **Local scratch handoff for extractors.** v1 streams every job input over per-job HTTP references ([ADR-0021](decisions/ADR-0021-extractor-sandbox-enforcement.md)) — least privilege, location-agnostic, no mounts. | Q61 | **Licence of the extractor SDK.** The contract is the plugin boundary and is published as a document (`openapi-extractor.json`), so an image implementing the six calls in any language owes this project nothing. The convenience SDK in [`extractors/`](extractors/README.md) is AGPL-3.0 like the rest of the repository, which means a third-party extractor that *imports* it inherits those terms — arguably against the spirit of [ADR-0002](decisions/ADR-0002-extractor-containers-fixed-api.md)'s third-party story, arguably fine since the contract needs no SDK. Deciding otherwise (a permissively licensed client package) would supersede part of [ADR-0016](decisions/ADR-0016-license-and-third-party-compliance.md) and therefore needs its own ADR. No third-party extractor exists yet, so nothing is blocked. | 🔴 |
| Q62 | **Tag usage counts at library scale.** Autocomplete ranks by how much the caller uses each tag ([F-003/FR-8](features/F-003-tagging.md)) and the count is computed per request — one grouped count over the page's tags, scoped to the caller's live files ([02 § Tag/FileTag](specs/02-domain-model.md#tag--filetag)). At a few tens of thousands of files that is milliseconds; a tag applied to a hundred thousand of them is a hundred thousand index entries per keystroke. The options are a maintained counter (cheap reads, and every writer has to reproduce the projection — curation *plus* machine claims *minus* rejections, per owner), a materialized view refreshed on a schedule (stale counts, no writer burden), or leaving it and capping candidates harder. Search facets in phase 3 need the same numbers over the same rows, so the answer belongs with them rather than ahead of them. | 🔴 deferred to phase 3 |
| Q63 | **Pruning superseded generations.** Reprocessing writes a new generation and keeps the old one — [ADR-0004](decisions/ADR-0004-tag-provenance-and-reprocessing.md) retains it for rollback "until explicitly pruned", and nothing prunes it yet. Phase 2 makes "replaced" a property of the *read* for tags (a claim counts only in its extractor's newest generation for that version — [02 § Tag/FileTag](specs/02-domain-model.md#tag--filetag)); `metadata_entry` and `segment` have the same column and no such filter, so after a reprocess a file's metadata list would show both generations. Deciding needs the rollback surface itself: what "roll back" means per version, whether a version carries a *current generation* pointer instead of a per-read maximum, and when a pruning job runs. Belongs with [F-009](features/F-009-reprocessing.md) in phase 5; until then nothing in the product triggers a second generation. | 🔴 deferred to phase 5 |
| Q64 | **A `section` anchor for documents without pages.** [F-004/FR-3](features/F-004-document-text-extraction.md) asks for "line-range (or section)" anchors, and [02 § Segment](specs/02-domain-model.md#segment) fixes the kind vocabulary at `page`, `time`, `line`, `sheet`, `region`, `whole` — there is no section.
